## 2. 현재 시점에서 시작한다면

가이드 작성일 2026-10-09는 원문 6주차 기간이다. **당시 저장소에서 구현 코드가 확인되지 않았다는 사실과 이전 활동을 실제로 하지 않았다는 판단은 다르다.** 2026-10-10에는 받은 데이터 점검과 법령 API 조회를 완료했고, 다음 작업을 [[09 실제 데이터와 법령 API 점검]]에 정리했다. 다른 위치의 학습 코드·실험 결과가 있으면 함께 확인한다.

앞선 작업이 아직 없다면 남은 6·9·10·11·13주차의 계획 시간은 합계 40시간이다. 앞선 24시간 분량을 모두 추가하면서 같은 범위를 약속하기 어렵기 때문에 다음처럼 범위를 좁혀 시작한다.

### 먼저 만드는 작은 실행 단위

1. 가상 근로계약서 3개와 OCR 입력 JSON을 만든다.
2. 임금·시간·기간 등 핵심 항목을 추출하고 원문을 연결한다.
3. 주의 쟁점 2~3종에 필요한 공개 근거를 검토해 등록한다.
4. 설명·추가 질문을 반환한다.
5. 같은 데이터 변환으로 20사례 학습 smoke test와 소규모 1차 LoRA를 실행한다.
6. dev 결과와 실제 남은 시간을 보고 10주차 범위를 확정한다.

학습 환경·라벨 검토가 늦어지면 해당 상태를 기록하고 교수 자문에서 일정·범위를 조정한다. 원문의 과거 날짜를 이미 완료한 활동처럼 보고하지 않는다.

## 3. 구현 순서와 의존성

| 순서 | 작업 | 먼저 필요한 것 | 작동 확인 방법 |
| --- | --- | --- | --- |
| 1 | 추출·원문 스키마 | 가상 계약서, OCR 블록 합의 | JSON 파일로 함수 호출 |
| 2 | 기존 모델 기준선 | ModelAdapter, 형식·원문 검증 | 동일 샘플 결과 저장 |
| 3 | 데이터 변환·분할 | 허용된 자료, 라벨 의미, 그룹 ID | train/dev/test 중복 검사 |
| 4 | 1차 학습 | 실행 장비, tokenizer, 작은 train | checkpoint 저장·재로드와 dev 비교 |
| 5 | 공개 근거 검색 | 검토된 출처·시점·쟁점 | gold 근거 top-5 확인 |
| 6 | 주의 조항과 질문 | 추출값, 근거, 상황 필드 | 정상·주의·불명확 분기 |
| 7 | 2차 학습·Agent | dev 오류표, 함수 계약 | 개선 결과와 상태 흐름 |
| 8 | 팀 통합·임대차 | 백엔드, 임대차 스키마·근거 | 제한된 세 시나리오 |
| 9 | 초안·번역 | 확인된 사실, 템플릿·용어집 | 중요 사실 일치 검사 |
| 10 | 최종 평가·기술도식 | 고정 버전, 잠근 test | 평가표·구현 구조 |

1~7은 전문기 혼자 고정 JSON 입력으로 개발할 수 있다. 실제 OCR·UI·보안·번역 검수는 담당자 협업이 필요한 단계다.

## 4. 기술 선택 결정표

| 결정 | 추천 시작점 | 바꿀 조건 | 내가 선택 |
| --- | --- | --- | --- |
| 첫 계약 유형 | 근로계약 | 임대차 데이터·검토 자원이 더 준비돼 있음 | 미정 |
| 서비스 기준 모델 | 샘플 비교가 좋은 API 또는 실행 가능한 로컬 모델 | 입력 전송 조건·비용·품질·장비 | 미정 |
| 학습 목표 | 조건 추출 LoRA | 추출이 충분히 좋고 검토된 쟁점 라벨이 확보됨 | 미정 |
| 학습 환경 | 보유 장비에 맞는 MLX 또는 TRL | 메모리·지원·속도 검증 실패 | 미정 |
| Agent 구현 | Python 상태 흐름 | 복잡한 장기 상태·분기가 실제로 필요함 | 미정 |
| RAG 저장소 | SQLite + NumPy, 작은 공개 자료 묶음 | 지식량·동시 사용자·운영 관리 요구 증가 | 미정 |
| 최초 문서 | 사실확인 요청문·상담 준비 요약서 | 검토된 고급 템플릿과 사실 검증 확보 | 미정 |
| 임대차 범위 | 보증금·기간·반환 관련 특약 | 자료·시간·평가셋이 확보됨 | 미정 |

추가 프레임워크는 실제 필요한 기능이 생겼을 때 선택한다. 초기에는 입력·출력 스키마와 평가셋이 라이브러리 선택보다 먼저다.

## 5. 일정이 부족할 때 줄일 순서

1. 계약 유형·쟁점 수를 줄이고 정답 검토를 유지한다.
2. 임대차는 제한된 항목·시나리오로 시연한다.
3. 초안은 한 가지 템플릿과 텍스트 출력부터 완성한다.
4. 번역은 검수된 설명·용어 묶음부터 제공한다.
5. LoRA 실험 규모를 줄여 실제 학습·재로드·평가 기록을 남긴다.
6. 다중 Agent, 여러 GPU 실험, 대규모 지식 수집, 파일 내보내기는 후순위로 둔다.

원문 근거 추적, 미확인 상태, train/test 분리, 실제 학습 전후 비교는 축소하지 않을 핵심이다.

## 6. 원문 최종 결과물과 연결

| 계획서의 결과물 | 전문기의 증거 |
| --- | --- |
| AI 계약서 분석 기술·데이터 조사 자료 | 데이터 manifest, 기술 선택표, 정제·라벨 규칙, 모델 비교 |
| 한·중·스페인어 법률용어·번역 자료 | 번역 입력 스키마, 숫자·출처 보존 검사, 담당자 검수 연결 |
| UI/UX·개인정보 보호·보안 설계 | 원문 근거 JSON, 상태·질문 API, 마스킹·삭제·로그 범위 |
| 주차별 모델·Agent 결과 | adapter, 실행 로그, 시나리오 결과, dev·최종 평가표 |
| 특허 명세서용 AI 처리 구조 | 구현된 단계·데이터 관계·분기·평가 결과의 도식 |

특허 기술구조는 실제 구현한 데이터 흐름을 기록한다. 일반적인 LLM·RAG·Agent 조합 자체를 새 기술로 단정하지 않고, 구현에서 어떤 구체적 처리와 효과를 확인했는지 정리한다.
