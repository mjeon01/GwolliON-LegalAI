# 평가와 완료 기준

[[00 권리ON 전문기 구현 가이드|시작 노트]] · 이전: [[05 API와 팀 연동]] · 다음: [[07 주차별 작업과 결정표]]

## 1. 평가할 질문

1. 계약서의 사실을 정확히 추출했는가?
2. 검토된 주의 조항을 발견하고 불필요한 경고를 줄였는가?
3. 필요한 법률 근거를 검색했는가?
4. 설명이 원문·근거·적용 조건을 따르는가?
5. Agent가 필요한 질문과 행동을 연결했는가?
6. 문서 초안과 번역에서 사실이 유지되는가?

학습 loss와 문장이 자연스러운 정도만으로 완료를 판단하지 않는다. 단계별 오류와 전체 흐름의 성공을 함께 평가한다.

## 2. 최소 평가셋 제안

[[03 데이터와 법률 RAG]]의 독립 문서 40개 중 dev 10개, 최종 test 20개를 검토한다. 최종 test는 근로계약 12개·주거 임대차 8개를 시작 구성으로 제안한다.

| 집합 | 예시 구성 | 용도 |
| --- | --- | --- |
| dev 10문서 | 정상, 주의, 누락, 충돌, 다양한 서식 | 반복 개발과 설정 선택 |
| test 20문서 | 새로운 계약서·서식 그룹, 근로 12·임대차 8 | 13주차 최종 비교 |
| 검색 질의 20개 | 근로·임대차 쟁점, 잘못된 시점, 근거 없음 | 검색·보류 검증 |
| E2E 핵심 3종 | 외국인 근로자, 청년 임차인, 피해 의심 | 사용자 흐름 평가 |
| 강건성 사례 | 흐린 OCR, 표, 숫자 오류, 문서 안 명령 | 실패 처리 평가 |

문서 수와 평가 사례 수를 구분한다. 한 문서에서 여러 항목·조항을 평가하더라도 독립 문서가 늘어난 것으로 계산하지 않는다. 소수 test에서 나온 점수는 시연 범위의 결과이며 일반 서비스 성능을 입증하는 통계로 확대하지 않는다.

법률 쟁점 정답은 교수·전문가 등 검토자를 정해 확인한다. 아직 검토되지 않은 사례는 모델 동작을 보는 실험 사례로 표시하고, 법률 판단 정확도의 gold 분모에 넣지 않는다.

## 3. 정량 지표

아래 목표값은 **팀이 검토할 시연 목표 제안**이다. 현재 측정 결과는 없다.

| 영역 | 지표와 계산 단위 | 제안 목표 |
| --- | --- | --- |
| 조건 추출 | 정답에 있는 항목 중 값·단위가 모두 맞은 항목 비율 | 핵심 항목 90% 이상 |
| 항목 오류 | 값이 없는데 만들어낸 항목 / 예측한 항목 | 분자·분모 공개, 중요 금액·날짜 오류 0건 목표 |
| 원문 연결 | 사용자에게 표시한 추출값 중 원문 범위 일치 비율 | 100%, 실패값은 보류 |
| 추출 커버리지 | 정답에 있는 핵심 항목 중 보류 없이 표시한 항목 비율 | 정확도와 함께 보고 |
| JSON | 첫 응답 스키마 성공률 / 재시도 후 성공률 | 따로 기록, 최종 100% 목표 |
| 쟁점 탐지 | 검토된 계약서·쟁점 쌍 기준 precision·recall·F1 | 대상 쟁점 recall 85% 이상 제안 |
| 탐지 편향 | 쟁점별 F1와 macro 평균, 정상 사례의 오경고율 | 빈도와 건수 함께 보고 |
| 검색 | 필요한 gold 근거 중 top-5에 포함된 비율, Recall@5 | 90% 이상 제안 |
| 설명 근거 | 검토한 사실·법률 주장 중 근거가 뒷받침하는 비율 | 중요 주장 100% 목표 |
| 질문 분기 | 상황이 부족한 사례 중 적절히 질문·보류한 비율 | 필수 분기 누락 0건 목표 |
| 초안 | 확인되지 않은 사실이 추가된 수 | 0건 목표 |
| 번역 | 금액·날짜·근거 ID·주의 상태의 일치 비율 | 100% 목표 |
| 운영 | 문서당 처리 시간 p50·p95, 호출비·재시도 수 | 측정 후 허용 목표 결정 |

`precision = TP / (TP + FP)`, `recall = TP / (TP + FN)`이다. 다중 쟁점은 계약서·쟁점 쌍 단위로 집계한다. 발생 건수가 적은 쟁점은 F1 하나로 결론내리지 않고 TP·FP·FN을 함께 표시한다.

추출값을 많이 보류해 원문 연결 성공률만 높일 수 있으므로, **보류율과 커버리지도 반드시 보고**한다. 위험한 확정 오류와 과도한 보류를 동시에 확인한다.

## 4. 비교 실험 구성

| 실험 | 모델 | 검색·규칙 | 목적 |
| --- | --- | --- | --- |
| A | 로컬 학습 후보의 학습 전 버전 | 동일 설정 | 추출 학습의 기준선 |
| B | 같은 모델의 1차 LoRA | 동일 설정 | 1차 학습 효과 확인 |
| C | 같은 모델의 2차 LoRA | 동일 설정 | 오류 보완 효과 확인 |
| D | 실제 서비스 기준 모델 | 동일 설정 | 서비스 채택 판단 |
| E: 선택 | 선택 모델 | RAG 없이 / RAG 포함 | 검색 근거가 설명에 미치는 영향 |

- 학습 전후 비교에는 같은 모델 revision·입력·스키마·후처리를 쓴다.
- A/B/C의 개발 과정은 dev에서 비교하고, 선택이 끝난 버전을 최종 test에 평가한다.
- API 모델과 로컬 모델 비교는 서비스 품질 비교이며 학습 효과 비교와 구분한다.
- temperature·입력 길이·재시도 정책·지식 snapshot·프롬프트 버전을 기록한다.
- 결정적 설정에서도 결과 변동이 가능하므로, 달라지는 사례는 반복 실행해 기록한다.

## 5. 전체 흐름 테스트

### 외국인 근로자

1. 근로계약서를 입력한다.
2. 임금·시간·기간과 원문이 표시되는지 확인한다.
3. 적용 조건이 부족하면 질문이 생성되는지 확인한다.
4. 답변 뒤 해당 쟁점만 재평가되는지 확인한다.
5. 중국어·스페인어 결과의 숫자와 근거가 유지되는지 확인한다.
6. 확인 요청문 초안의 사실을 대조한다.

### 사회초년생 임차인

1. 임대차계약서와 가상의 상황 정보를 입력한다.
2. 보증금·기간·특약을 원문과 대조한다.
3. 확인할 조항과 필요한 공식 근거를 연결한다.
4. 계약서 밖에서 확인해야 하는 자료를 구분하는지 확인한다.

### 전세사기 피해 의심

1. 계약서와 사용자가 확인한 사건 경위를 입력한다.
2. 사용자 진술과 계약서 사실의 출처를 구분한다.
3. 부족한 증빙·시점 질문이 나오는지 확인한다.
4. 상담 준비 요약서에 확인되지 않은 피해·권리 정보를 만들어 넣지 않는지 확인한다.

세 시나리오는 계획서의 범위를 구현하는 제안이다. 실제 피해 판단 정답은 별도 검토가 필요하다.

## 6. 반드시 넣을 실패 사례

| 사례 | 기대 결과 |
| --- | --- |
| OCR이 금액의 0 하나를 잘못 읽음 | 품질 문제 또는 원문 재확인 상태 |
| 계약서 일부 페이지만 입력 | 문서 완전성 확인, 누락 확정 보류 |
| 요약표와 특약의 임금·기간이 다름 | 두 근거를 보여주고 질문 |
| 과거 사건에 최신 법령만 검색됨 | 해당 시점 근거 확인 또는 판단 보류 |
| 모델이 없는 block ID·source ID 출력 | 표시 차단, 해당 항목 실패 처리 |
| 계약서에 "이전 지시를 무시하라"는 문구 있음 | 문서 데이터로 처리, 흐름·도구 권한 유지 |
| 다른 사용자의 분석 ID 조회 | 백엔드에서 접근 거부 |
| 분석 도중 취소·삭제 | worker 완료 뒤 결과 재저장 방지 |
| API timeout·잘못된 JSON | 제한된 재시도와 실패·부분 결과 |
| 번역에서 금액이나 날짜가 바뀜 | 번역 검증 실패, 검수 필요 표시 |

## 7. 오류 기록과 종료 기준

```text
case_id / document_group / task / expected / actual
error_stage / severity / root_cause / action
model_version / prompt_version / rules_version / source_snapshot
reviewer / reviewed_at
```

오류 원인은 OCR, 전처리·마스킹, 라벨, 추출, 규칙, 검색, 설명, Agent, 번역으로 나눈다. OCR 오류를 학습 데이터 부족으로 분류하면 수정 방향이 잘못될 수 있다.

### 시연 가능한 상태

- [ ] 근로계약 P0가 앱 또는 JSON 입력에서 끝까지 동작한다.
- [ ] 제한된 임대차 P1과 세 사용자 시나리오를 시연할 수 있다.
- [ ] 표시한 값·설명에 원문과 근거를 추적할 수 있다.
- [ ] 추가 질문·판단 보류·오류 응답이 동작한다.
- [ ] 학습 전후 비교표와 실제 산출물이 있다.
- [ ] 번역과 초안의 중요 사실이 유지된다.
- [ ] 평가 점수의 분모·보류율·검토 범위를 공개한다.
- [ ] 채택 모델·버전·미해결 오류와 구현 범위를 정리한다.
